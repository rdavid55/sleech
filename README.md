# СЛИЧ / Sleech

Сервис согласования измерений в цепочке поставок. Команда «Соавторы»: Русишвили Давид и Ефимов Аман.

Версия Liquid Glass: клиентский путь и серверные кабинеты от 31 октября 2026 года; сохранены исправления аудита и 3D-инструменты. Статический сайт находится в папке `docs/`.

[Журнал аудита и проверки исправлений](audit/2026-10-28.md).

## Опубликовать сайт

В настройках репозитория откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Deploy from a branch**, затем ветку **main** и папку **/docs**, нажмите **Save**.

После успешной публикации сайт будет доступен по адресу https://rdavid55.github.io/sleech/.

## Возможности

- Русская и английская версии, услуги, база знаний и публичные материалы проекта.
- 3D-коллекция из девяти деталей: синхронное вращение мышью и пальцем, проекции и карта отклонений.
- Паспорта деталей, полные таблицы учебных измерений, экспорт CSV/JSON и передача результата в сравнение.
- Расчёт сметы и экономического эффекта.
- Работа с CSV, локальный кейс и экспорт отчёта.
- Выбор временных либо сохраняемых на устройстве черновиков.

Локальные расчёты обрабатываются в браузере. Новая форма подбирает следующий шаг и передаёт описание в кабинет только после подтверждения. На GitHub Pages отправка выключена до подключения серверного адреса: статический хостинг не запускает базу. Кабинет не использует старый Sites. Учебные данные и плановые цены обозначены на страницах.

Шрифты Onest и Unbounded размещены локально; файлы лицензий находятся в `docs/assets/fonts/`.

## Локальный запуск

```bash
python3 -m http.server 8000 --directory docs
```

Откройте http://localhost:8000.

## 3D-коллекция

Страница `docs/3d.html` (EN: `docs/en/3d.html`) содержит вал, втулку, диск, фланцевую ступицу, двухручьевой шкив, конический переходник, корпус подшипника, монтажную плиту и угловой кронштейн.

Потяните любую модель мышью или пальцем: номинальная форма и пример с отклонениями вращаются вместе по обеим осям. Два пальца меняют масштаб. Кнопки выбирают проекцию; стрелки работают с клавиатуры, `Home` сбрасывает вид. Ползунков камеры и измерения нет. Направление измерения выбирается отдельными кнопками и не зависит от камеры.

Демонстрационные выступы, впадины, овальность, изменение конусного профиля, смещение оси и неперпендикулярность заданы математически. Режим 250× увеличивает геометрические отклонения; таблица и экспорт сохраняют исходные числа. Данные, материалы и допустимые интервалы вымышленные; это не производственный контроль и не решение о годности.

Геометрия рисуется локально в Canvas 2D с ортографической 3D-проекцией. Модели кэшируются; перерисовка происходит только при изменении вида. Внешние библиотеки и сетевые запросы для просмотра не нужны.

Проверка геометрии, расчётов, импорта, экспорта и хранения черновиков (Node.js):

```bash
node --test tests/*.test.cjs
```


## Клиентский путь и кабинеты

- Главная → `start.html`: вопросы под задачу, требования, осторожная подсказка по тексту и предварительный подбор из актуального каталога.
- `solution.html`: проблема заказчика, выдаваемые материалы, границы, цена и стадия проекта.
- `portal.html`: кабинет своей компании либо рабочий реестр команды по серверной роли.
- `server/`: Node.js 24 + SQLite, отдельные организации, устойчивые идентификаторы, защита повторной отправки, согласование версий объёма и цены, история, внутренние заметки, приватные вложения, приглашения коллег.
- Аккаунты команды создаются только серверной командой, не публичной регистрацией. База и файлы не попадают в Git.

```bash
npm test
npm start
```

Полный сайт и API локально: http://localhost:8080. Установка npm-зависимостей не требуется.

**Подключение в интернете:** [server/README.md](server/README.md). Предоставлены Dockerfile, Compose и HTTPS reverse proxy; адрес хостинга и доступы не выдуманы. `docs/assets/portal-config.js` задаёт origin API после его развёртывания.

**Актуальная публичная основа продукта:** `docs/product-focus.json` и страница `docs/solution.html`. Старые DOCX/PDF/PPTX этой правкой автоматически не изменены.

Проверки: `npm test`, `python3 tools/check-links.py`. В CI используется Node.js 24. Приём реальных производственных данных требует отдельно согласованных исполнителя, размещения, сроков хранения и договорных условий.
